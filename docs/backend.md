# Бэкенд: функции Yandex Cloud

Фаза 2 — вход подписчиков Boosty (план — `docs/SPEC.md`). Сайт остаётся статикой в бакете `espanolcontim.ru` (`docs/object-storage.md`). Всё, что за ним, — в отдельном каталоге `backend`, куда не дотягивается ключ деплоя сайта:

```
сайт https://espanolcontim.ru ──► API Gateway https://api.espanolcontim.ru ──► функция api
                                                                                  │
таймер раз в час ──► функция sync ──► Boosty                                      │
                          │                                                       │
                          └──────────► приватный бакет espanolcontim-private ◄────┘
```

Лимиты бесплатного уровня и оценка нагрузки — `docs/object-storage.md`, «Фаза 2». Как устроены `sync` и `api` и что лежит в бакете — README, «Функция sync» и «Функция api».

## Что создаём

| Что | Имя | Зачем |
| --- | --- | --- |
| Каталог | `backend` | всё фазы 2, отдельно от сайта (каталог `site`) |
| Приватный бакет | `espanolcontim-private` | токены Boosty, кэш подписчиков, `overrides.json`; потом — платные уроки |
| Сервисный аккаунт | `sync` | от его имени работают функция `sync` и её таймер: роли `storage.editor` и `functions.functionInvoker` на каталог `backend`. Ключей у него нет: функция получает IAM-токен сама |
| Функция | `sync` | Node.js 22, `index.handler`, 128 МБ, 60 секунд |
| Триггер | `sync-hourly` | таймер, каждый час в :00 по UTC |
| Сервисный аккаунт | `api` | от его имени работает функция `api` (читает подписчиков и уроки, пишет, когда отправлялись письма) и API Gateway вызывает её: те же две роли на каталог `backend` |
| Функция | `api` | Node.js 22, `index.handler`, 128 МБ, 30 секунд |
| API Gateway | `api` | спецификация — `functions/api/gateway.yaml`: все адреса — в функцию `api` |
| Сертификат | `api-espanolcontim-ru` | Let's Encrypt на `api.espanolcontim.ru`, для домена шлюза |

Секреты: токены Boosty — в бакете (`boosty/auth.json`, функция сама их обновляет); `EMAIL_HASH_SECRET` (общий у `sync` и `api`), `SESSION_SECRET`, `SMTP_PASSWORD` — в переменных окружения функций. Lockbox не используем: он платный, а переменные функции видит только владелец облака.

## Что сделать Тимуру

Токены и ключи в чат не вставлять. Всё — в https://console.yandex.cloud под тем же Яндекс ID, что сайт.

### sync

1. **Каталог.** Облако → «Создать каталог» → имя `backend`. Галочку «Создать сеть по умолчанию» снять: сеть не нужна. «Создать».
2. **Приватный бакет.** Object Storage (вверху выбран каталог `backend`) → «Создать бакет»:
   - имя `espanolcontim-private`;
   - максимальный размер — 1 ГБ (чтобы случайно не платить за хранение);
   - «Чтение объектов», «Чтение списка объектов» и «Чтение настроек» — **ограниченный доступ**, не «Для всех»: в бакете токены и подписчики;
   - класс хранилища — стандартное; шифрование и версионирование не включать.
3. **Сервисный аккаунт.**
   1. Identity and Access Management (https://console.yandex.cloud/link/iam, каталог `backend`) → «Создать сервисный аккаунт» → имя `sync` → «Создать».
   2. Каталог `backend` → «Права доступа» → «Назначить роли» → «Сервисные аккаунты» → `sync` → «Добавить роль» `storage.editor`, ещё раз «Добавить роль» `functions.functionInvoker` → «Сохранить».
   3. Ключи для `sync` не создавать.
4. **Токены Boosty в бакет.** Бакет `espanolcontim-private` → «Создать папку» → `boosty` → открыть её → «Загрузить» → файл `auth.json` из папки проекта: `espanolcontim/.bucket/boosty/auth.json`. Папка `.bucket` скрытая: в окне выбора файла её показывает Ctrl+H. В бакете должен получиться объект `boosty/auth.json`.
5. **Функция.** Cloud Functions (каталог `backend`) → «Создать функцию» → имя `sync` → «Создать». В редакторе:
   - среда выполнения — **Node.js 22**; галочку «Добавить файлы с примерами кода» снять → «Продолжить»;
   - способ — «ZIP-архив» → файл `espanolcontim/functions/sync/dist/sync.zip` (уже собран; заново — `npm run functions:build`);
   - точка входа — `index.handler`;
   - таймаут — 60 секунд, память — 128 МБ;
   - сервисный аккаунт — `sync`;
   - переменные окружения — три, имя ровно как здесь:

     | Ключ | Значение |
     | --- | --- |
     | `BUCKET` | `espanolcontim-private` |
     | `BOOSTY_BLOG` | `espanolcontim` |
     | `EMAIL_HASH_SECRET` | из файла `espanolcontim/.env`: строка `EMAIL_HASH_SECRET=…`, всё после `=` |

   - логирование — как предложено (лог-группа каталога по умолчанию);
   - «Сохранить изменения». Публичной функцию не делать: её вызывает только таймер.
6. **Проверка.** Функция `sync` → «Тестирование» → тег `$latest`, входные данные `{}` → «Запустить тест». Должно быть «Выполнена», а в ответе — `"total": 2, "paid": 0` и `"refreshed": false`. В бакете появится `subscribers.json`. Если ошибка — прислать Claude её текст из поля «Ответ функции» или из «Логов»: токенов в нём нет.
7. **Таймер.** Cloud Functions → «Триггеры» → «Создать триггер»:
   - имя `sync-hourly`, тип — «Таймер»;
   - cron-выражение `0 * ? * * *` — каждый час в :00 (по UTC);
   - функция `sync`, тег `$latest`, сервисный аккаунт `sync`;
   - повторные запросы и Dead Letter Queue — не включать → «Создать».

   Через час в «Логах» функции появится строка `{"message":"sync", …}`.

Дальше токенами владеет облако: локальная копия `.bucket/boosty/auth.json` удаляется — две копии одного входа в Boosty, скорее всего, выбивали бы друг друга (refresh token после обновления новый). Для `npm run sync:local` понадобится свой, отдельный вход в Boosty (README, «Функция sync»).

10. **Сервисный аккаунт `api`.** От его имени функция читает бакет, а шлюз вызывает функцию.
    1. Identity and Access Management (https://console.yandex.cloud/link/iam, вверху выбран каталог `backend`) → «Создать сервисный аккаунт» → имя `api` → «Создать». Роли в этом окне можно не добавлять — их дают на следующем шаге.
    2. Страница каталога `backend` (в списке облака слева — `backend`) → «Права доступа». В списке пока только ты и `sync`: аккаунта без ролей там нет, его туда добавляет эта кнопка — «Назначить роли» (вверху справа; в старой консоли — «Настроить доступ») → в окне выбрать пользователя: вкладка «Сервисные аккаунты» → `api` → «Добавить роль» `storage.editor` → ещё раз «Добавить роль» `functions.functionInvoker` → «Сохранить». Не через «…» у строки `sync`: так роли достанутся ему. В окне должно быть «Ресурс — `backend`, каталог». Если там «`api`, сервисный аккаунт» и предупреждение «Вы назначаете доступ субъекту на самого себя» — это «Права доступа» на странице самого аккаунта, а не каталога: «Отмена» и в каталог.
    3. Проверить: в «Правах доступа» каталога `backend` у `api` — две роли, как у `sync`.
    4. Ключи для `api` не создавать: функция получает IAM-токен сама, шлюз — тоже.
11. **Функция `api`.**
    1. Секрет для сессий. В терминале — `openssl rand -hex 32`: напечатается строка из 64 знаков `0–9a-f`. Это `SESSION_SECRET` для облака: он нужен только в переменной функции (пункт 3), больше его нигде хранить не надо — ни в `.env`, ни в чате. В `.env` свой, для компьютера: так сессии с компьютера в облаке не действуют. Потеряется — не страшно: новый секрет, подписчики один раз войдут заново.
    2. Cloud Functions (https://console.yandex.cloud/link/functions, каталог `backend`) → «Создать функцию» → имя `api` → «Создать». Откроется «Редактор»:
       - среда выполнения — **Node.js 22**; галочку «Добавить файлы с примерами кода» снять → «Продолжить»;
       - способ — «ZIP-архив» → файл `espanolcontim/functions/api/dist/api.zip` (собран 30.10.2026; заново — `npm run functions:build`);
       - точка входа — `index.handler`;
       - таймаут — 30 секунд, память — 128 МБ;
       - сервисный аккаунт — `api` (не `sync`).
    3. Ниже, «Переменные окружения» → «Добавить переменную окружения» пять раз. Ключ — ровно как здесь, значение — без кавычек и пробелов:

       | Ключ | Значение |
       | --- | --- |
       | `BUCKET` | `espanolcontim-private` |
       | `EMAIL_HASH_SECRET` | из `espanolcontim/.env`: строка `EMAIL_HASH_SECRET=…`, всё после `=` (тот же, что у `sync`; другой — и `api` не узнает ни одной почты) |
       | `SESSION_SECRET` | строка из пункта 1 |
       | `SMTP_USER` | `espanolcontim@yandex.ru` |
       | `SMTP_PASSWORD` | из `espanolcontim/.env`: строка `SMTP_PASSWORD=…`, всё после `=` (пароль приложения из шага 9) |

       Lockbox («Секреты Lockbox») не трогать.
    4. Логирование — как предложено → «Сохранить изменения». Появится версия с тегом `$latest`.
    5. Публичной функцию не делать (в «Обзоре» переключатель «Публичная функция» выключен): её вызывает только шлюз, от имени `api`.
    6. **Проверка.** Вкладка «Тестирование» → тег `$latest`, во «Входные данные» — вместо того, что там есть:

       ```json
       {"httpMethod": "POST", "path": "/auth/request", "headers": {}, "body": "{\"email\": \"test@example.com\"}"}
       ```

       → «Запустить тест». Должно быть «Выполнена», в ответе — `"statusCode": 200` и `"body": "{\"ok\":true}"`, в «Логах» — `"result":"unknown"`: функция прочла `subscribers.json` из бакета и такой почты там не нашла, письмо не ушло. Ошибка — прислать Claude текст из «Ответа функции» или «Логов» (секретов там нет).
12. **API Gateway.** Нужны два идентификатора — это не секреты:
    - функции: Cloud Functions → `api` → «Обзор» → «Идентификатор» (начинается с `d4e`);
    - сервисного аккаунта: Identity and Access Management → «Сервисные аккаунты» → `api` → «Идентификатор» (начинается с `aje`).

    1. API Gateway (https://console.yandex.cloud/link/api-gateway, каталог `backend`) → «Создать API-шлюз»: имя `api`, описание и таймаут — не трогать.
    2. «Спецификация»: стереть пример и вставить всё содержимое `espanolcontim/functions/api/gateway.yaml`. В нём заменить вместе с угловыми скобками: `<ID функции api>` — идентификатором функции, `<ID сервисного аккаунта api>` — идентификатором аккаунта. Отступы не менять: в YAML они значимы. Должно получиться так:

       ```yaml
               function_id: d4e…
               service_account_id: aje…
       ```

    3. Логирование — как предложено → «Создать». Шлюз будет готов через полминуты.
    4. На странице шлюза — «Служебный домен» вида `d5d….apigw.yandexcloud.net`.

       - имя — `api` (окончание `.espanolcontim.ru.` консоль допишет сама);
       - тип — `CNAME`;
       - TTL — `600`;
       - значение — служебный домен из пункта 2 и **точка на конце**: `d5d….apigw.yandexcloud.net.` (без точки DNS допишет к нему `espanolcontim.ru`, и адрес не найдётся).

       → «Создать». В списке записей появится строка `api.espanolcontim.ru.` — `CNAME` — `600` — `d5d….apigw.yandexcloud.net.`, рядом с `_acme-challenge.api`.

       - домен — `api.espanolcontim.ru`;
       - сертификат — `api-espanolcontim-ru`.

       → «Подключить». В списке доменов шлюза появится `api.espanolcontim.ru`. Если у домена есть кнопка «Создать запись» в Cloud DNS — не нажимать: запись уже есть (пункт 3), а зона в другом каталоге.

Проверить с компьютера: `dig @77.88.8.8 api.espanolcontim.ru CNAME +short` должно показать служебный домен с точкой. Только что создали запись — подождать 15 минут: «записи нет» DNS-серверы помнят столько;
       - «Подключение не защищено» / ошибка сертификата — домен не подключён к шлюзу или подключён с другим сертификатом (пункт 4); сразу после подключения — подождать ещё несколько минут;
       - другой ответ вместо `invalid_token` — домен подключён не к тому шлюзу: в шаге 12.5 через служебный домен всё работало?
    6. Написать Claude: «api развёрнут» и служебный домен шлюза (не секрет). Он проверит адрес снаружи: сертификат, ответы на вход, CORS для сайта и что чужим сайтам браузер ответ не покажет.

15. **Новая версия `api`.** Шлюз сам подставляет `Access-Control-Allow-Origin: *`, если функция этот заголовок не прислала, — так чужие сайты могли читать ответы API. Теперь функция присылает его всегда (`functions/api/src/http.ts`). Залить:
    1. Cloud Functions (каталог `backend`) → `api` → «Редактор» → способ «ZIP-архив» → файл `espanolcontim/functions/api/dist/api.zip`. Папки `dist` в git нет: на другом компьютере сначала `git pull` и `npm run functions:build`. Остальное — среда, точка входа, таймаут, аккаунт, переменные — консоль берёт из прошлой версии, не менять.
    2. «Сохранить изменения» → появится новая версия с тегом `$latest`; шлюз вызывает `$latest`, так что больше ничего делать не нужно.
    3. Написать Claude: «api обновлён» — он проверит, что чужому сайту теперь приходит `Access-Control-Allow-Origin: https://espanolcontim.ru`, а не `*`.

    «Service temporarily unavailable» при сохранении — сбой у Yandex Cloud: подождать, обновить страницу (архив прикрепить заново), попробовать ещё раз, можно с выключенным VPN; сбои — на https://status.yandex.cloud. Не проходит совсем — обход: загрузить `api.zip` в бакет `espanolcontim-private` (например, `functions/api.zip`) и в «Редакторе» выбрать способ «Object Storage» с этим файлом.

Как залить новую версию любой функции потом — так же: `npm run functions:build` → «Редактор» → ZIP-архив → «Сохранить изменения».

## Если что-то сломалось

- **В логах «Boosty не обновил токен»** — вход в Boosty, от которого токены, закрыт (нажали «Выйти» или Boosty отозвал). Взять токены заново (README, «Функция sync») и загрузить `boosty/auth.json` в бакет поверх старого.
- **«Boosty вернул 0 активных платных подписчиков, а в кэше N»** — скорее всего, Boosty поменял ответ: прислать Claude. Если подписчиков правда не осталось — удалить `subscribers.json` из бакета.
- **Пока `sync` падает, вход работает по последнему удачному списку.** Новые подписчики войти не смогут, ушедшие — ещё не потеряют доступ.
- **В логах `api` — `mail_failed` с `EAUTH`** — пароль приложения неверный или отозван (шаг 9): создать новый и заменить `SMTP_PASSWORD` у функции `api`. `This user does not have access rights to this service` — выключен доступ для почтовых программ (шаг 9.1), `Invalid user or password` — пароль не тот (шаг 9.2).
- **`SESSION_SECRET` утёк** — заменить у функции `api` на новый: все сессии станут недействительны, подписчикам придётся войти заново. Ничего другого он не открывает.
