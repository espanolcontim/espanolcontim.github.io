# Español con Tim — сайт курса

Сайт курса «Испанский с нуля» (YouTube-канал «Español con Tim») для русскоязычных учеников, которые начинают с нуля. На сайте: конспекты уроков с удобной навигацией, тренажёр перевода, интервальное повторение, проверки после уроков. Часть материалов бесплатна, остальное — для подписчиков Boosty, которые входят на сайт по почте.

Подробная спецификация и план по фазам — `docs/SPEC.md`. Сверяйся с ним перед работой; закончив пункт, отмечай его там. Где остановились, что ждёт решения и что дальше — `docs/STATUS.md`: читай в начале работы, обновляй в конце каждого пункта. Как развернуть проект на новом компьютере — `README.md`.

## Репозитории и папки

```
<рабочая папка>/          ← НЕ git-репозиторий, просто папка
  espanolcontim/          ← этот репозиторий (GitHub espanolcontim/espanolcontim.github.io, публичный; позже — и SourceCraft)
  video-lessons/          ← отдельный репозиторий (GitHub): уроки, конспекты, упражнения в JSON и PDF
```

- Это два независимых репозитория, лежащие рядом. Не вкладывай один в другой и не создавай общий репозиторий.
- Claude Code запускается из `espanolcontim` с доступом к соседней папке: `claude --add-dir ../video-lessons`.
- `../video-lessons` — **только чтение**. Ничего там не меняй и не предлагай менять формат его файлов. Чего сайту не хватает (стабильные id, ссылки на видео, проверки после урока), живёт в этом репозитории — см. «Схема контента» в `docs/SPEC.md`. Форматы источника — `docs/content-sources.md`.

## Жёсткие правила

1. **Репозиторий публичный** (бесплатные GitHub Pages и SourceCraft Sites публикуют только из публичного репозитория). В git НИКОГДА не попадают:
   - платный контент — он живёт только в `content/private/` (в `.gitignore`) и в приватном бакете Yandex Cloud;
   - токены Boosty, секреты JWT, SMTP-пароли, `.env`;
   - данные подписчиков: email, Boosty id, дампы ответов API Boosty.
   Сомневаешься, попадёт ли файл в git, — проверь `.gitignore` и спроси.
2. **Аудитория в России.** Ничего не грузить с Cloudflare, Google Fonts и других CDN, которые в РФ замедляются или блокируются. Шрифты и библиотеки — только из npm в собственный бандл. Внешние скрипты — только Яндекс Метрика (когда дойдём).
3. **Видео на сайт не встраиваем.** Только ссылки на YouTube (см. `docs/SPEC.md`).
4. **Хостинг — только статика.** Сейчас GitHub Pages: `https://espanolcontim.github.io/`, деплой — `.github/workflows/deploy.yml` при push в `main`. Позже сайт будет и на SourceCraft Sites: `https://espanolcontim.sourcecraft.site/`. На обоих адресах сайт открывается в корне. В сайте нет серверного кода; бэкенд — функции Yandex Cloud в папке `functions/`.
5. **Ноль рублей.** Всё должно укладываться в бесплатные тарифы (GitHub Pages и Actions для публичного репозитория, SourceCraft Sites, free tier Yandex Cloud). Если решение требует платного сервиса — сначала спроси.

## Стек

- **Astro** (статическая генерация) + **React-острова** для интерактива, TypeScript strict.
  Почему не SPA: бесплатные конспекты должны индексироваться Яндексом, а у статического хостинга нет серверного рендеринга. Каждая страница урока — отдельный HTML-файл.
- **zod** — схемы контента: единый контракт для импорта, сайта и функций.
- Стили: CSS-переменные из `apps/web/src/shared/styles/theme.css` (светлая и тёмная тема; сами темы — в `styles/themes/`, активная — одна строка `@import` в `theme.css`); в `.astro` — scoped `<style>`, в React-островах — CSS Modules. Без UI-фреймворков, если нет веской причины.
- Шрифты — из npm: Manrope (`@fontsource-variable/manrope`), транскрипция — Noto Sans (`@fontsource/noto-sans`): в Manrope нет знаков МФА.
- Бэкенд: Yandex Cloud Functions (Node.js, TypeScript), API Gateway, Object Storage.
- Тесты: Vitest. Node 22.23+ (так требует Astro 7), npm workspaces.
- TypeScript 6.0, не 7: TS 7 пока не поддерживают `astro check` и языковой сервер Astro.
- Линтер — oxlint (как в `video-lessons`, с правилами `jsx-a11y`), форматтер — Prettier с `prettier-plugin-astro`.
- Скрипты (`scripts/`) запускаются обычным `node`: Node 22.18+ сам выполняет TypeScript. Поэтому импорты — с расширением `.ts`, и только стираемый синтаксис (`erasableSyntaxOnly`): без `enum` и `constructor(private x)`.

## Архитектура

Feature-first. Доступ к данным — через репозитории, зависимости внедряются через конструктор, композиционный корень один на среду: для сборки и для браузера.

```
apps/web/                      Astro-сайт
  src/features/
    lessons/                   список уроков, страница урока, конспект
    practice/                  тренажёр: перевод, пропуски, выбор, порядок слов
    review/                    интервальное повторение (Repaso)
    exams/                     проверка после урока, итоговый тест уровня
    auth/                      вход подписчиков Boosty по ссылке на почту, сессия
  src/shared/                  UI-компоненты, утилиты
  src/app/container.ts         композиционный корень сборки (весь контент — в браузер не импортировать)
  src/app/browser.ts           композиционный корень браузера: острова и скрипты (прогресс)
packages/content/              zod-схемы, типы, правила доступа, проверка ответов, алгоритм повторения
functions/api/                 вход, сессии, выдача платных уроков
functions/sync/                выгрузка подписчиков Boosty по таймеру
scripts/                       импорт контента, выгрузка платного в бакет
content/public/                бесплатный контент + метаданные всех уроков (коммитится)
content/private/               платный контент (в .gitignore!)
content/ids.lock.json          постоянные id предложений (коммитится)
content/videos.json            ссылки на видео уроков (ведёт Тимур)
docs/SPEC.md
```

Репозитории и сервисы:
- `LessonRepository` — `list()`, `getMeta(id)`, `getBody(id)`. Бесплатные части берутся из `content/public` (`StaticLessonRepository`), платные — через API (`ApiLessonRepository`). Компоненты не знают, откуда пришли данные.
- `ProgressRepository` — прогресс по урокам и карточки повторения. Сейчас `LocalStorageProgressRepository`: все обращения к storage в try/catch, сайт работает и без него.
- `AuthService` — запрос ссылки, обмен её на сессию, продление, выход.

## Контент

- Контракт — zod-схемы в `packages/content`. `npm run content:import` читает `../video-lessons` (путь в `CONTENT_SOURCE`, по умолчанию `../video-lessons`), приводит данные к схеме, валидирует и раскладывает по `content/public` и `content/private` по правилам доступа.
- **Правила доступа — один конфиг** (`packages/content/src/access.ts`): что бесплатно и что платно, задаётся по уровню и по части урока (выжимка, конспект, упражнения, проверка). Модель доступа может поменяться — не зашивай её в компоненты.
- Метаданные ВСЕХ уроков (номер, название, уровень, состав, что платно) публичны: платные уроки видны в списке с пометкой «в подписке „Практика“».
- **Стабильные id.** У каждого предложения и упражнения постоянный id (например, `a0-01-s03`), на нём держится прогресс повторения. Перегенерация урока не должна менять id существующих элементов. id выдаёт импорт и хранит в `content/ids.lock.json` (коммитится; только хэши фраз, без текста).
- **Слайдов и текста за кадром на сайте нет.** JSON урока — только источник данных для конспекта, допматериалов и упражнений; `notes` слайдов не импортируются.

## Предметные правила

- Язык интерфейса — русский. Испанский текст размечается `lang="es"`.
- Метод — Мишель Томас: новые слова появляются только внутри предложений, никаких списков слов.
- Проверка перевода — общая функция в `packages/content`, обязательно с тестами:
  - несколько допустимых вариантов ответа, первый — эталон;
  - нормализация регистра, пробелов, пунктуации, знаков ¿ ¡;
  - ответ без диакритики (á, é, í, ó, ú, ü, ñ) засчитывается как «почти верно» с подсказкой;
  - при ошибке показываем эталон и пояснение.
- Под полем ввода — панель кнопок `á é í ó ú ü ñ ¿ ¡`: ученики печатают с телефона и с русской раскладки.
- Повторение (Repaso): единица — предложение из пройденных уроков; простой алгоритм (Лейтнер или SM-2), с тестами.
- Mobile-first: большинство учеников с телефона. Доступность: управление с клавиатуры, контраст, `prefers-reduced-motion`.
- Цвета — только через CSS-переменные из одного файла темы. Ни одного захардкоженного цвета в компонентах: палитра должна меняться в одном месте (см. «Оформление» в `docs/SPEC.md`).

## Команды

- `npm run dev` — сайт локально; `npm run build` — `astro check` и сборка в `apps/web/dist/`; `npm run preview` — посмотреть сборку.
- `npm test` — Vitest по всем пакетам (тесты рядом с кодом, `*.test.ts`); `npm run typecheck` — tsc для пакетов и `astro check`.
- `npm run lint` — oxlint; `npm run format` / `npm run format:check` — Prettier (`.md` не форматирует).
- `npm run content:import` — импорт из `../video-lessons`: все уроки, `-- 1 8 11` — только эти, `-- --check` — проверить, ничего не записывая.
- `npm run content:upload` — появится в фазе 2.

## Как работаем

- Идём по фазам из `docs/SPEC.md`, по одному пункту за раз. Перед крупным решением коротко предложи вариант и спроси.
- Новые зависимости — только с обоснованием; следи за размером бандла.
- Идентификаторы — на английском; тексты интерфейса и комментарии — на русском.
- Перед коммитом: `npm test` и `npm run build` проходят; в индексе git нет файлов из `content/private`, `.env`, дампов и токенов.
